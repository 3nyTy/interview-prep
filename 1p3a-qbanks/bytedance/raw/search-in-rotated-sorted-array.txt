Search in Rotated Sorted Array
LeetCode 33: search for a target in an ascending array rotated at an unknown pivot and return its index or `-1`. A current intern-screen follow-up removes the distinct-values guarantee, requiring explicit handling of duplicate boundary values.

Requirements

The input array was originally sorted in ascending order and then rotated at an unknown pivot.

Given a target value, return its index if present; otherwise return -1.

The base version contains distinct integers and expects O(log n) running time.

Minority variant: values are not guaranteed to be distinct; clarify the degraded worst-case behavior before coding.

Examples

Input: nums = [4,5,6,7,0,1,2], target = 0
Output: 4

Input: nums = [4,5,6,7,0,1,2], target = 3
Output: -1

Notes

The distinct-values version appeared late in a multi-round SDE loop after a broad technical oral drill.

The duplicate-values follow-up appeared in a 2027 summer-intern screen after cache and database fundamentals.

Boundary decisions must be dry-run aloud; unexplained branch conditions and silent off-by-one fixes weaken otherwise correct code.

Preparation

Write the modified binary search from memory and state which half is sorted before deciding where the target can lie.

Extend the implementation for duplicate boundary values and explain why shrinking equal endpoints can be necessary.

Drill the one-element array, no-rotation case, pivot at either boundary, absent targets, and repeated values.
