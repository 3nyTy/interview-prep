NYC Green Taxi Data Science Challenge
Analyze September 2015 NYC green-taxi trips in a seven-day take-home: load and profile the data, examine trip-distance behavior by time and airport usage, model tip percentage, then complete one advanced extension in distributions, visualization, spatial search, anomaly detection, or an original direction.

Requirements

Programmatically download and load the September 2015 NYC Green Taxi trip-record dataset, then report the loaded row and column counts.

Plot a histogram of Trip Distance; describe visible structure and propose hypotheses for it.

Group trip distance by hour of day and report the mean and median. Identify trips that originate or terminate at an NYC-area airport, then report the transaction count, average fare, and other notable characteristics.

Derive tip as a percentage of total fare. Build a predictive model for that percentage, estimate performance on an appropriate sample, and show the work.

Complete exactly one of the following extensions; if more than one is submitted, only the first is scored:

Distributions: derive average trip speed, test whether average speeds are materially the same across all weeks of September, explain any differences, and form a hypothesis for speed as a function of time of day.

Visualization: create a static or interactive view of intra- versus inter-borough traffic and explain what it reveals about green-taxi usage.

Search: implement a function that takes a latitude-longitude point P and returns the k nearest trip origins. Discuss how pickup time could support real-time ride-sharing matching, and analyze time and space complexity.

Anomaly detection: identify abnormal traffic or behavior by day, time, or location; develop a process using time-series analysis, clustering, or another method; and attempt to explain the anomalies.

Own curiosity: formulate and answer a distinct question that highlights relevant skills and analytical philosophy.

Notes

Start with schema, null, duplicate, timestamp, coordinate, distance, and fare validation. Keep an explicit record of exclusions so every aggregate and model result can be reproduced.

Define hour-of-day and airport classification rules before computing slices, report each slice's sample size, and compare robust statistics when outliers make the mean unstable.

For tip-percentage modeling, separate predictors available before the outcome from fields that directly encode the tip or final total. Use a held-out or time-ordered split, compare against a simple baseline, and inspect both aggregate error and tail behavior.

Treat the deliverable as a handoff to another data scientist: connect intent, code, analysis, and conclusions rather than submitting a bare notebook.

Include assumptions, documented and well-structured code, run instructions, unsuccessful approaches, unfinished ideas worth pursuing, a thorough write-up, and pertinent visualizations.

Use only the assigned Workday ID and initials in submission content and filenames. Zip the work without the downloaded dataset and submit it by email within seven days.

Cite any online materials, libraries, or borrowed code. Do not publish any part of the interview submission.

Preparation

Rehearse a reproducible notebook-to-handoff workflow: scripted download, schema and row-count checks, documented transformations, plots, model evaluation, and clean run instructions.

Practice explaining every analytical choice in business-readable language, including assumptions, failed attempts, limitations, and what additional work would be done with more time.

Time-box a full dry run so the required four sections are complete before committing to one advanced extension.
