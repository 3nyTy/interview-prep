Valid Word Abbreviation (LeetCode 408) with Follow-Up Variant
Validate whether an abbreviation legally represents a word by interpreting each number as a run of skipped characters and matching literal letters in place. The follow-up reverses the task: generate every legal abbreviation while merging adjacent omitted characters into a single count.

Requirements

Inputs are a full word and a proposed abbreviation.

A number in the abbreviation means to skip that many characters in the word; consecutive digits form one complete number.

Literal letters in the abbreviation must match the corresponding word characters exactly.

A numeric token with a leading zero is invalid.

Reject any skip that moves beyond the end of the word, and return true only when both pointers finish simultaneously.

Follow-up: given a word, generate all legal abbreviations. Each character can be retained or compressed, and adjacent compressed characters must be represented by one combined count.

Examples

i18n is a valid abbreviation of internationalization.

Notes

Scan the word and abbreviation with two indices. When the abbreviation index reaches a digit, reject a leading zero, parse the entire digit run into one skip count, and advance the word index once; otherwise match one literal character. Reject overshoot and accept only if both indices finish together. The validator runs in O(|word| + |abbr|) time and O(1) extra space.

For generation, use DFS over the word with a pending omitted-character count. The omit branch increments the count; the keep branch flushes that count before appending the literal character; flush once more at the leaf. This emits all 2^n abbreviations in output-proportional O(n * 2^n) time with O(n) recursion depth.

Multi-digit skips are a parsing trap; consuming digits independently changes the contract.

The edge cases were expected before coding: leading zero, skip overflow, and one input ending before the other. Calling them out early was treated as a positive signal.

The s10n / substitution example was marked invalid even though it conflicts with the stated skip-count rule. Clarify the exact target spelling and expected result before coding rather than hard-coding that outcome.

Preparation

Write the validator from scratch and table-drive leading-zero, multi-digit, overshoot, literal-mismatch, and mismatched-ending cases.

Implement the generator follow-up separately, then explain how the recursion prevents adjacent numeric tokens from being emitted independently.
